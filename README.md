# FVCOM on Olivia

[![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.24304444.svg)](https://doi.org/10.5281/zenodo.24304444)

Containerized FVCOM (branch `v5.1.0_icecode`, spherical, PETSc semi-implicit) for the
Olivia cluster (Sigma2/NRIS). Runs under Apptainer; 1-node and 2-node SLURM job
scripts included.

## Image

    apptainer pull --force docker://ghcr.io/j34ni/fvcom-container-on-olivia/fvcom:mpich5.1

`:mpich5.1` is the current image (parallel NetCDF, consistent MPICH stack);
`apptainer pull` names the file `fvcom_mpich5.1.sif`.

## Set up

The job scripts use `$PROJECT`, a variable you define yourself, pointing to your
project work area. The jobs inherit it via `#SBATCH --export=ALL`:

    export PROJECT=/cluster/projects/nnXXXXk/<user>

Set your own project number in both scripts (`#SBATCH --account=nnXXXXk`).
The job scripts expect `fvcom_mpich5.1.sif` in the current directory (set
`SIF` to use another image file). End-to-end procedure from the provided
case data: `E2E.md`.

## Run

    sbatch job-favne-hot-1n.sh    # 1 node  x 128 ranks, small partition
    sbatch job-favne-hot-2n.sh    # 2 nodes x  64 ranks, large partition

The 1-node job keeps all MPI traffic node-local. The 2-node job sends every
inter-rank exchange through the Slingshot interconnect (`ofi`/`cxi`): it
demonstrates that the container's MPI stack works across nodes, not just
inside one.

Success markers, in order, in the job output:

1. domain decomposition table with 128 non-empty rank rows
2. `PETSc SETUP        : COMPLETE!`
3. `IINT ... SIMTIME ... SECS/IT` lines advancing
4. `output/FavneChild1_0001.nc` and `output/FavneChild1_restart_0001.nc` written

## Inputs

The example case (FavneChild1, hot start) reads these case files, provided by
the model user, from `$PROJECT/FavneChild1-hot` (2-node jobs symlink them into
a per-run directory):

    FavneChild1_grd.dat              grid connectivity
    FavneChild1_dep.dat              depth
    FavneChild1_sigma.dat            sigma layers
    FavneChild1_cor.dat              Coriolis coefficient
    FavneChild1_spg.dat              smoothing parameters
    FavneChild1_obc.dat              open boundaries
    FavneChild1_wnd_0723.nc          wind forcing
    FavneChild1_heat_0723.nc         heat flux forcing
    FavneChild1_prate_0723.nc        precipitation
    FavneChild1_restart_0723.nc      restart fields (hot start)
    FavneChild1NH_restart_0723.nc

Only `FavneChild1_run.nml` is adjusted relative to the production namelist: the
startup block is set to a hot start from `FavneChild1_restart_0723.nc`,
`END_DATE = '2025-07-23 02:00:00'` for a short validation window, and
`OUTPUT_DIR` is rewritten per run by the 2-node job script (the 1-node job
writes into the case directory). All the case files above are used unmodified;
the `FavneChild1.part` decomposition file is regenerated by METIS at run time.

## Results

FavneChild1 hot start (restart IINT 4838435 -> 2025-07-23 02:00, 128 ranks total):

| ranks        | s/step | wall    |
|--------------|--------|---------|
| 1 node x 128 | 0.1452 | 1:09:14 |
| 2 nodes x 64 | 0.1012 | 0:48:49 |

Measured on the previous image (MPICH 5.0.2, serial NetCDF; PETSc r3 + hypre,
BoomerAMG), jobs 2681304 / 2681487, 28800 steps. s/step = median over steps
21..N. `medians.sh` recomputes these medians from the two job outputs;
`plots/` holds figures from the same runs.

## Build

    docker build -t fvcom .

Source and revision are overridable with build args `FVCOM_REPO` and `FVCOM_REF`.
The image ships the `fvcom` binary in `/opt/fvcom` on `PATH`.

## Source

The `v5.1.0_icecode` branch carries the port to METIS 5 and modern PETSc APIs,
merged upstream as https://github.com/akvaplan-niva/FVCOM_dev/pull/1

The build clones https://github.com/akvaplan-niva/FVCOM_dev at the merge commit
`632c1feb`; `FVCOM_REPO` and `FVCOM_REF` accept another repository and commit
(or branch) when needed.
